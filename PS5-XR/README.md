# AR инструкция по обслуживанию PlayStation 5

Учебный прототип по теме «Разработка инструкций дополненной реальности по обслуживанию оборудования».
Редактор: **Unity 6.3 LTS, 6000.3.8f1**. AR Foundation и ARCore XR Plugin: **6.3.5**.

## Открытие проекта

1. Unity Hub → Projects → Add → Add project from disk.
2. Выберите именно папку `PS5-XR`, содержащую `Assets`, `Packages`, `ProjectSettings`.
3. Откройте редактором 6000.3.8f1. При первом открытии дождитесь импорта пакетов.
4. После успешной компиляции сцена `Assets/Scenes/Maintenance.unity` создаётся автоматически,
   если её ещё нет. Откройте её и нажмите Play.
5. Кнопкой «Модель» выберите семейство консоли. Подтверждайте выполнение шага и нажимайте «Далее».

Если сцена отсутствует: меню **PS5 XR → Создать или обновить сцену**.
Это меню пересоздаёт сцену и настройки приложения; не запускайте его после ручного изменения сцены без сохранения копии.
Обычная работа не требует пересоздания сцены.

Если редактор уже открыт в Safe Mode после первого импорта: **Assets → Refresh** (Ctrl+R),
дождитесь компиляции, затем **Exit Safe Mode**. Ошибки тестовых сборок пакетов исправлены:
их asmdef отключены ограничением `PS5_XR_RUN_VENDOR_TESTS`, которое не нужно добавлять
в Scripting Define Symbols для этого приложения.

После смены Active Input Handling на Input System требуется полностью закрыть редактор
и заново открыть проект через Hub. Остановка Play и Ctrl+R не перезапускают нативный ввод.
Если интерфейс перестал принимать нажатия после обновления, сначала выполните этот перезапуск.
UI-модуль явно подключает стандартные действия мыши, клавиатуры и касаний.

## Что делает прототип

- Отображает 10 последовательных шагов отключения, снятия наружных крышек, визуального осмотра и обратной установки.
- Показывает текст, предупреждение, прогресс и стрелку для текущего шага.
- Предлагает варианты текста для обычной PS5, Slim и Pro; выбранное семейство фиксируется при начале сеанса.
- Требует подтверждения выполнения; при отсутствии отслеживания маркера переход вперёд блокируется.
- Разрешает вернуться к предыдущему шагу; повторное подтверждение не создаёт дубликат выполненного шага.
- Сохраняет завершение в JSON на ПК, через **Java + SQLite** на Android.
- Кнопка «Сначала» сбрасывает проход. Начатый, но брошенный сеанс остаётся незавершённым.

## Проверка без телефона

В окне Unity **Game** выберите **PS5 XR → Чёткое изображение в Game**:
команда отключает **Low Resolution Aspect Ratios**, который был включён в сохранённой раскладке.
Для просмотра мобильного интерфейса выберите формат **9:16** или разрешение **1080 × 1920**.
При увеличении маленького изображения выше 100% пиксели всё равно становятся заметными.
Текст теперь использует TextMeshPro и заранее подготовленный шрифт PT Sans с кириллицей.

Готовая проверенная сборка для Windows находится в `Builds/Windows/PS5-XR.exe`.
Можно запустить её двойным щелчком, без открытия Unity. Сборка запускается в режиме ПК.

На ПК приложение использует условную схему корпуса и имитацию маркера. Это позволяет проверять UI,
порядок шагов и сохранение, но не проверяет камеру, ARCore или JNI.
Кнопка «Маркер: показать / скрыть» имитирует потерю отслеживания.

Схема не является точной 3D-моделью PS5. Стрелки на ней демонстрационные.
Инструкции не требуют снятия вентилятора, винтов внутренних узлов или вскрытия блока питания.

## Что нужно перед настоящей демонстрацией

1. Узнать полный CFI-номер консоли и сверить выбранные шаги с руководством для этого номера.
2. Получить фотографии обеих сторон и размеры расположения маркера относительно деталей.
3. Настроить `Assets/Resources/EquipmentLayout.asset`: `exactCfiModel`, `calibratedModel`, координаты targets в метрах.
4. Включить `calibratedForRealConsole` только после проверки положения всех стрелок первой стороны.
5. После переворота/перемещения PS5 нужна новая привязка. В текущем прототипе реальные стрелки второй стороны скрыты;
   текст продолжает отображаться. Для стрелок на второй стороне понадобится отдельный профиль положения.
6. Проверить устройство по списку Google ARCore. Печатный маркер: `Docs/marker-print.html`, размер 12 × 12 см.

Sony публикует разные способы снятия крышек для семейств CFI-1000 и CFI-2000/7000.
В приложении есть ссылка на первоисточник. Выбор семейства не заменяет проверку точной модели.

## Подготовка Android

На компьютере при начале работы модуль Android Build Support отсутствовал.

1. Unity Hub → Installs → 6000.3.8f1 → Add modules → Android Build Support,
   Android SDK & NDK Tools, OpenJDK.
2. Unity → File → Build Profiles → Android → Switch Platform.
3. Edit → Project Settings → XR Plug-in Management → Android → включите **ARCore**.
   Если Project Validation показывает исправления, выполните обязательные для ARCore.
4. Сцена `Maintenance` должна входить в список сборки. Настроены портретная ориентация, ARM64,
   IL2CPP и минимальный API 26. При необходимости версия API уточняется по выбранному телефону.
5. Соберите APK в `Builds/Android`. На совместимом телефоне установите Google Play Services for AR,
   APK и предоставьте доступ к камере.
6. На Android приложение стартует в AR-режиме. Наведите камеру на плоский маркер при хорошем освещении.

Реальное AR-отслеживание и Java/SQLite пока требуют проверки на устройстве.
Подробный порядок первой проверки — `Docs/phone-check.md`.
До обнаружения маркера показывается экран поиска; после обнаружения появляется
инструкция и контур маркера. Реальные стрелки на детали появляются только после калибровки координат.
ARCore может продолжать оценивать положение ранее обнаруженного неподвижного маркера вне кадра;
приложение проверяет состояние Tracking, а не факт нахождения изображения в кадре.

## Java в проекте

`Assets/Plugins/Android/` содержит:

- `SessionRepository.java` — интерфейс хранилища;
- `SqliteSessionRepository.java` — SQLiteOpenHelper и реализация интерфейса;
- `MaintenanceBridge.java` — входная точка, которую Unity вызывает через AndroidJavaObject;
- `SessionRules.java` — проверка границ шагов и полноты инструкции;
- `proguard-user.txt` — сохранение классов при обработке Java-кода.

При подтверждении первого шага C# вызывает Java begin, на каждом шаге — recordStep,
при завершении — finish. Это используемый компонент Android-приложения.
На ПК применяется отдельная JSON-реализация того же C# интерфейса.

## Организация исходников

| Путь | Назначение |
| --- | --- |
| Assets/Scripts | Инструкция, конечный автомат, UI, AR и мост к Java |
| Assets/Resources/ps5-instruction.json | Шаги и тексты |
| Assets/Resources/MarkerLibrary.asset | Эталонное изображение и физический размер |
| Assets/Resources/EquipmentLayout.asset | Координаты и статус калибровки |
| Assets/Plugins/Android | Java и SQLite |
| Assets/Editor/ProjectSetup.cs | Создание сцены, проверки, сборка ПК |
| Docs | Модели, ручные проверки, источники и печатный маркер |
| Tools | Независимая проверка Java правил |

Служебные папки Library, Temp, Logs, UserSettings и сборки исключены из Git.
Файлы `.meta` и `Packages/packages-lock.json` следует хранить вместе с исходниками.

Фактические результаты проверок и ограничения приведены в `Docs/verification.md`.
AR-пакеты включены локально, чтобы не скачивать их повторно. Unity Package Manager также обращается
к реестру за метаданными редактора; при сетевой ошибке `ECONNRESET` импорт может остановиться.
Локальные архивы не заменяют доступ к этим служебным метаданным.
Пакеты в подпапках `Packages/com.unity.*` содержат исходный официальный код и лицензии;
их нужно сохранять в репозитории. `Vendor` содержит резервные архивы и исключён из Git.
